# ScreenSender

[English](README.md) | **Русский**

Управление компьютером с Windows из браузера телефона. ScreenSender показывает рабочий стол
на веб-странице, а вы кликаете, прокручиваете и печатаете на нём с телефона. Работает в локальной
сети или через интернет по проброшенному порту. На телефон ничего ставить не нужно.

Это один файл на Python и две HTML-страницы, рассчитанные на медленный мобильный интернет:
передаются только изменившиеся части экрана, поэтому неподвижный экран не тратит трафик вовсе.

## Возможности

- **Мало трафика.** Картинка разбита на плитки, и передаются только изменившиеся плитки.
  При увеличении передаётся только видимая часть. Набор текста в документе стоит несколько КБ.
- **Быстрый захват.** DXGI Desktop Duplication снимает кадр 4K примерно за 5 мс и сообщает,
  когда ничего не изменилось. Запасной вариант — GDI.
- **Управление касаниями.** Касание, двойное касание, удержание для правого клика, удержание
  и перетаскивание для выделения текста и переноса окон, щипок для увеличения, прокрутка двумя пальцами.
- **Панель клавиатуры.** Набранный на телефоне текст сразу печатается на ПК на любом языке,
  какая бы раскладка ни стояла на ПК. Залипающие Ctrl/Alt/Shift/Win, стрелки, Esc, Tab, Alt+Tab,
  диспетчер задач и другое.
- **Вставка с телефона.** Длинные тексты и код приходят мгновенно через буфер обмена ПК,
  без автоотступов редактора.
- **Несколько мониторов.** Переключение между мониторами или все сразу.
- **Пресеты качества** для медленной и быстрой связи. Когда экран замер, картинка досылается
  в высоком качестве, и после прокрутки текст снова чёткий.
- **Страница входа** и необязательный **HTTPS** с самоподписанным сертификатом, который создаётся
  при первом запуске.

## Требования

- Windows 10 или 11 на ПК. Мышь и клавиатура работают через Windows API; на других системах
  страница только показывает экран.
- Python 3.10 или новее.
- Любой современный браузер на телефоне: Chrome, Safari, Firefox.

## Быстрый старт

```
git clone https://github.com/parhipov/ScreenSender.git
cd ScreenSender
pip install -r requirements.txt
copy config.example.json config.json
```

Откройте `config.json`, задайте `username` и `password` и запустите сервер:

```
python server.py
```

Если `config.json` нет, при первом запуске он создаётся со значениями по умолчанию.
При запуске сервер печатает адреса, которые нужно открыть:

```
Capturing monitor 1: 2560x1440 at (0,0), capture=auto
  LAN:      http://192.168.1.20:8005/
  Internet: public_ip is not set in config.json
  Login:    alice / correct-horse-battery-staple
Press Ctrl+C to stop
```

Откройте адрес из строки `LAN` на телефоне, подключённом к той же Wi-Fi сети, и войдите с логином
и паролем из `config.json`. Браузер помнит вход 30 дней.
При первом запуске брандмауэр Windows спросит, можно ли Python принимать подключения.
Разрешите, иначе телефон не достучится до ПК.

### Доступ из интернета

1. Пробросьте на роутере TCP-порт (по умолчанию 8005) на этот ПК.
2. Включите `"https": true` и задайте надёжный пароль в `config.json`.
   Перед этим прочитайте раздел [Безопасность](#безопасность).
3. По желанию укажите в `public_ip` свой внешний IP. Он нужен только для того, чтобы напечатать
   адрес для интернета и вписать его в сертификат.

## Как пользоваться

| На телефоне | На ПК |
|---|---|
| Касание | Левый клик |
| Двойное касание | Двойной клик |
| Удержать и отпустить | Правый клик |
| Удержать и вести | Перетаскивание левой кнопкой: выделение текста, перенос окон и файлов |
| Щипок | Увеличение картинки; дальше передаётся только видимая часть |
| Перетаскивание одним пальцем (при увеличении) | Осмотреться |
| Два пальца вверх-вниз или вбок | Колесо мыши |

В браузере на компьютере мышь работает как обычно, включая перетаскивание.

### Панель кнопок

Кнопки в правом верхнем углу. Интерфейс на русском, если браузер предпочитает русский язык,
иначе на английском.

| Кнопка | Что делает |
|---|---|
| **🖥 1** | Переключает монитор: 1, 2, …, потом все сразу. Видна, только если мониторов несколько. |
| **🎚 Эконом / Обычно / Чётко** | Качество картинки. Браузер его запоминает. |
| **Клики** | Включает и выключает управление мышью; удобно, когда осматриваете увеличенную картинку. |
| **⌨** | Открывает панель клавиатуры. |
| **⛶** | Полный экран. |
| **☰** | Прячет остальные кнопки и строку состояния. |

В левом верхнем углу видно способ захвата (DXGI или GDI), число обновлений в секунду и КБ/с.

### Клавиатура

На панели **⌨** есть поле ввода и два ряда клавиш.

- Всё, что вы набираете в поле, сразу печатается на ПК. Автозамена и подсказки слов тоже работают:
  страница отправляет только разницу.
- **Ctrl, Alt, Shift, Win залипают.** Нажмите Ctrl, потом букву — получится Ctrl+буква.
  С русской раскладкой на телефоне это тоже работает: Ctrl+С уходит как Ctrl+C.
  Повторное нажатие на активный модификатор отправляет его самого; Win отдельно открывает меню «Пуск».
  Залипшие модификаторы действуют и на следующее касание картинки: Shift+касание расширяет выделение,
  Ctrl+касание добавляет к нему.
- Остальные клавиши: Esc, Tab, Backspace, Del, Enter, стрелки, Home, End, PgUp, PgDn, Alt+Tab,
  F5, «Копир.» (Ctrl+C), «Отмена» (Ctrl+Z) и Ctrl+V, который вставляет буфер обмена ПК.
- Третий ряд: диспетчер задач, Win+R (выполнить), Win+D (рабочий стол), Win+E (проводник), Win+Tab
  и клавиша контекстного меню.
- В браузере на компьютере, когда поле в фокусе, работает и обычная клавиатура, включая сочетания клавиш.

### Вставка с телефона

Удерживайте поле ввода и выберите **Вставить** или нажмите **📋 С телефона**, чтобы прочитать
буфер телефона напрямую (для этого нужен HTTPS). Текст кладётся в буфер обмена ПК и вставляется
через Ctrl+V, поэтому длинные тексты и код приходят мгновенно, а редакторы не добавляют отступ
к каждой строке. Ctrl+V в браузере на компьютере делает то же самое. Учтите, что прежнее содержимое
буфера обмена ПК при этом заменяется.

## Настройки

Настройки лежат в `config.json` рядом с `server.py`. После изменения перезапустите сервер.

| Ключ | По умолчанию | Значение |
|---|---|---|
| `host` | `"0.0.0.0"` | Адрес, на котором слушает сервер. `0.0.0.0` — все сетевые интерфейсы. |
| `port` | `8005` | Порт. |
| `https` | `false` | Работать по HTTPS с самоподписанным сертификатом (см. [HTTPS](#https)). |
| `public_ip` | `""` | Внешний IP или имя хоста. Только печатается при запуске и вписывается в сертификат. |
| `username`, `password` | `"admin"`, `"change-me"` | Логин и пароль для входа. При их смене все выходят из системы. |
| `monitor` | `1` | Монитор при запуске: `1`, `2`, … или `0` — все сразу. Переключается со страницы. |
| `capture` | `"auto"` | `auto` или `dxgi`: DXGI Desktop Duplication, а если он недоступен — GDI. `gdi`: только GDI. |
| `fps` | `10` | Частота захвата. Чаще этого телефон обновления не получает. |
| `max_width` | `1600` | Картинка уменьшается до этой ширины. Для медленного канала уменьшите (например, `1280`); `0` — полное разрешение. |
| `tile_size` | `64` | Размер плитки в пикселях (не меньше 16). Передаются только изменившиеся плитки. |
| `draw_cursor` | `true` | Показывать на странице указатель мыши ПК. |
| `allow_input` | `true` | Разрешить клики, прокрутку и ввод. `false` — только просмотр. |

## HTTPS

С `"https": true` сервер при первом запуске создаёт `cert.pem` и `key.pem` и работает только по HTTPS.
Сертификат действует 800 дней и пересоздаётся, когда истечёт. В него вписаны IP в локальной сети,
`public_ip`, `127.0.0.1` и `localhost`. Если у ПК сменился IP в локальной сети, удалите `cert.pem`
и перезапустите сервер, чтобы получить новый сертификат.

Браузер телефона один раз предупредит о неизвестном сертификате; выберите «Продолжить», и он это запомнит.
Чтобы предупреждения не было вовсе, установите сертификат на телефон как доверенный корневой.
Откройте `https://<ПК>:8005/cert`, затем:

- **Android:** Настройки → Безопасность → Шифрование и учётные данные → Установка сертификата →
  Сертификат ЦС. Точный путь зависит от производителя.
- **iPhone:** установите скачанный профиль в Настройки → Основные → VPN и управление устройством,
  затем включите полное доверие в Настройки → Основные → Об этом устройстве → Доверие сертификатам.

HTTPS нужен и для кнопки **📋 С телефона**: браузеры дают странице читать буфер обмена только по HTTPS.

## Безопасность

Тот, кто вошёл, полностью управляет вашим ПК. Прежде чем открывать порт в интернет:

- **Используйте длинный случайный пароль.** После неверного пароля сервер ждёт секунду,
  но параллельный перебор это не останавливает.
- **Используйте HTTPS.** По обычному HTTP пароль, картинка экрана и всё, что вы печатаете,
  идут в открытом виде. Вместо встроенного HTTPS можно поставить перед сервером обратный прокси
  с настоящим сертификатом (например, [Caddy](https://caddyserver.com/)).
- **Не отдавайте никому `key.pem`.** Сертификат является сертификатом ЦС, поэтому владелец `key.pem`
  может выпустить сертификат для любого сайта, и телефон, который доверяет этому сертификату, его примет.
  `key.pem` и `cert.pem` уже есть в `.gitignore`. Когда перестанете пользоваться ScreenSender,
  удалите сертификат с телефона.
- Вход действует 30 дней с последнего визита. Смена пароля, а также удаление `secret.key`
  с перезапуском сервера разлогинивают все устройства.
- Если нужен только просмотр, поставьте `"allow_input": false`.

## Работа без присмотра

Если ScreenSender — ваш единственный доступ к далёкому ПК, папка `deploy/` настраивает его так,
чтобы он держался сам: страж перезапускает сервер, если тот завершился или перестал отвечать, задачи
планировщика запускают его при входе в систему, а скрипт обновления забирает изменения из git,
проверяет, что новая версия работает, и откатывается, если нет. Сервер тогда работает от имени
администратора и может управлять окнами с повышенными правами; `install.ps1 -AdminShell` ещё и
добавляет админ-шелл, который открывается без окна UAC, — иначе на него удалённо не ответить. В [CLAUDE.md](CLAUDE.md) по шагам описаны установка, список
того, что сделать перед отъездом (автовход, без сна, без блокировки, отключения питания), и обновление.
Файл написан для Claude Code, но и человек может по нему пройти (он на английском).

## Замечания и ограничения

- DXGI не видит экран блокировки и окна UAC. При сбое DXGI следующие 30 секунд используется GDI,
  потом DXGI пробуется снова.
- Экран блокировки и окна UAC на защищённом рабочем столе через ScreenSender не видны и не управляются.
  Если это ваш единственный доступ, ПК не должен блокироваться; см. «Работа без присмотра».
- Окна программ, запущенных от имени администратора, принимают ввод, только если сервер тоже
  запущен от имени администратора.
- У всех зрителей одна картинка: переключение монитора меняет его для всех.
- Текст печатается как символы Unicode. Некоторые программы, читающие коды клавиш напрямую
  (например, игры), могут его не принять.
- Нет звука, передачи файлов и копирования с ПК на телефон.

## Как это устроено

- **Захват.** Один поток снимает экран с частотой `fps`, уменьшает до `max_width` и сравнивает
  с предыдущим кадром по плиткам. Каждая плитка помнит кадр, в котором она последний раз изменилась.
  Если никто не смотрит, захват не идёт; через 30 секунд простоя устройство захвата освобождается.
- **Состояние зрителя.** Каждая вкладка браузера — отдельный зритель. Сервер помнит, какую версию
  каждой плитки зритель уже нарисовал, поэтому на каждый запрос отдаёт только недостающие плитки
  и только в той области, которую показывает страница (плюс запас в одну плитку).
- **Long polling.** `GET /frame` ждёт до 5 секунд, пока для этого зрителя не появится что-то новое.
  Следующее обновление страница запрашивает только после того, как нарисовала предыдущее,
  поэтому на медленной связи падает частота кадров, а не растёт задержка.
- **Кодирование.** Небольшие изменившиеся области идут в WebP. Если обновить нужно больше половины
  видимой области, она уходит одной картинкой: пока экран движется — в JPEG, который кодируется намного
  быстрее, иначе — в высоком качестве. Через 0,7 с без изменений плитки, отправленные в низком качестве,
  досылаются в высоком.
- **Формат обновления.** 4 байта длины заголовка (big-endian), JSON-заголовок (размер картинки,
  положение курсора, координаты и размеры прямоугольников), затем куски изображения подряд.
- **Ввод.** Текст отправляется событиями `SendInput` с символами Unicode, клавиши — событиями
  виртуальных клавиш, клики и колесо — через `mouse_event`, вставляемый текст — через буфер обмена Win32.
